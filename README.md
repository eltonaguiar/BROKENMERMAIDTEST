# BROKENMERMAIDTEST — AI Swarm Acceptance Test Suite

A deliberately broken Mermaid diagram test suite used to evaluate AI swarms' ability to diagnose, fix, and validate code autonomously.

## What This Repo Contains

| File | Description |
|------|-------------|
| `index.html` | Working baseline flowchart (renders correctly) |
| `case-a-unquoted-parens.html` | Case A: Unquoted parentheses in `RESTMessageV2.execute()` label |
| `case-b-unbalanced-brackets.html` | Case B: Unbalanced brackets `[` without `]` |
| `case-c-unclosed-subgraph.html` | Case C: `subgraph` opened but never closed with `end` |
| `case-d-type-not-line1.html` | Case D: Diagram type not on line 1 (leading blank/comment) |
| `case-e-pipe-in-label.html` | Case E: Pipe `\|` character in plain bracket label |
| `case-f-raw-jekyll.html` | Case F: Jekyll shim skips block (first non-blank line is not diagram keyword) |
| `.github/workflows/pages.yml` | GitHub Actions deploy to GitHub Pages |

Each broken case page includes its own diagnosis and suggested fix inline.

## Swarm Evaluation Results

### Test Method

Each AI swarm was given the broken mermaid diagram and asked to:
1. Diagnose the root cause
2. Output a corrected mermaid diagram (≥2 nodes, ≥1 edge, diagram type on line 1)
3. Re-validate locally against mermaid@10.9.1
4. Push the fix to GitHub Pages

All fixes were validated with Playwright (headless Chromium) confirming SVG render with zero "Syntax error in text" errors.

### Key Findings

1. **Free models are as capable as paid** for mermaid fix tasks — all solved in 1 attempt at ~$0.001 each
2. **Context length is minimal** — ~663 chars per task; even small models handle this easily
3. **Thinking models output to `reasoning_content`** — LOCAL_CHAT and LOCAL_CODE put their response in `reasoning_content`, not `content`. Swarms must read both fields.
4. **Retry logic is essential** — 3 models needed a second attempt after validation feedback
5. **Cost is trivial** — ~$0.001 per task; ~250,000 tasks per $250

### Swarm Architecture Used

**CombineTeam** — N-model parallel consensus:
- Multiple models called in parallel via LiteLLM proxy (`:4000`)
- Health gate counts both `content` and `reasoning_content` as valid output
- First valid fix wins; others discarded
- Up to 3 retry attempts with error feedback

### Fallback Model Chain (when :4000 proxy is down)

```
Primary free:   ULTRA_FREE_CLOUD_FAST → ULTRA_FREE_NVIDIA → ULTRA_FREE_GEMINI
Fallback free:  ULTRA_FREE_KILO → ULTRA_FREE_LOCAL_CODE → ULTRA_FREE_LOCAL_CHAT (ollama keyless)
Paid:           ULTRA_PAID_MODE → PAID-DEEPSEEK-PRO → PAID-DEEPSEEK-FLASH
Decision only:  SUBQ_FREE → SUBQ_TOKEN (SubQ Snap 1.2 — PASS/FAIL verdicts only)
```

## How to Run

```bash
# Install
git clone https://github.com/eltonaguiar/SWARM_CONSOLIDATED.git
cd SWARM_CONSOLIDATED
python3 -m pip install -r requirements.txt

# Run swarm fix (broken mermaid → fix → validate → push)
python3 swarm_e2e_fix.py

# Run multi-model evaluation
python3 swarm_model_eval.py

# Run unified swarm with architecture choice
python3 swarm_unified.py "fix this mermaid" --architecture combine --model ULTRA_FREE_CLOUD_FAST

# Via AI_MENU
tools/ai_menu.sh swarm-unified
tools/ai_menu.sh swarm-fix
tools/ai_menu.sh swarm-eval

# Deploy the swarm (portable, Linux + Windows)
python3 deploy.py --install --test
# or
bash deploy.sh
```

## Deployable Swarm

The full swarm system is at [eltonaguiar/SWARM_CONSOLIDATED](https://github.com/eltonaguiar/SWARM_CONSOLIDATED) — includes:
- `swarm_unified.py` — unified runner for all 6 architectures (combine, debate, coding, pr_review, ruflo, hermes)
- `swarm_task.py` — original unified swarm with coordinator + QA loop
- `swarm_model_eval.py` — multi-model evaluation harness
- `swarm_e2e_fix.py` — end-to-end fix workflow
- `probe_providers.py` — probes and ranks available LLM providers with fallback chain
- `subq_translation_proxy.py` — SubQ Snap 1.2 → OpenAI-compatible translation proxy
- `deploy.py` / `deploy.sh` — one-command deploy (Linux + Windows)
- `.env.example` — environment configuration template
- `requirements.txt` — minimal runtime dependencies
- `SWARM_ARCHITECTURE_COMPARISON.md` — full architecture comparison

## FREELLM

The LiteLLM proxy configuration and FREELLM harvest source is at [eltonaguiar/FREELLM](https://github.com/eltonaguiar/FREELLM). The `litellm_config.runtime.yaml` includes SUBQ_FREE and SUBQ_TOKEN entries routed through a local translation proxy (`tools/subq_translation_proxy.py`) since SubQ's `/v1/systemone` endpoint is not OpenAI-compatible.
